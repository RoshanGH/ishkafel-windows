## 接手之前先看一眼：`ishkafel status`

**不管是刚开始、还是接着上次干，第一条命令都是它。**

```bash
ishkafel status            # 所有任务：干到哪了、下一步敲什么
ishkafel status <任务>      # 只看一条
ishkafel status --no-json  # 人看的版式
```

它报三样东西：

1. **每一步做完没有、做了多少**（照流程排：台词 → 打标 → 音色 → 配音 →
   挑镜头 → 配乐 → 导出）
2. **下一步照着敲的那条命令**，带真实 id 和行号
3. **现场情况**：这条任务此刻被谁占着、它正在干什么、最后一次改动是什么时候

为什么每次都要先跑它：

- **活儿被打断是常态**——人按了停、你的命令超时、app 关掉了、隔了一天回来。
  不看一眼就从头走一遍流程，等于重新打标（十几分钟、几十次识图）、
  重新配音（一轮 TTS），**全是白花的钱**
- **人在你不在的时候多半动过手**：自己挑了几个镜头、改了断句、换了音色。
  `updatedAt` 和你记得的对不上，就先看清他改了什么，别一上来就覆盖
- 它也会告诉你**哪一步其实已经做完了**——真机上有过：以为打标打完了，
  status 一看还差 7 镜

## 这个工具在做什么

做**竖屏口播短视频**。核心机制只有一句话：**台词决定时间，画面填进去**。

台词读多久，那一段就多长；画面被切、被变速，去凑那个长度——反过来
永远不成立。这条贯穿全部功能，看不懂哪里出错时先回到它。

## 两条线，先选一条

它们是**平级**的，不是主从。第一件事是判断走哪条：

| | **替换裂变** | **脚本成片** |
|---|---|---|
| 干什么 | 以片找片、换画面 | 从台词造新片 |
| 台词从哪来 | 从一条现成的片子里扒出来 | 自己写，或从参考片提取 |
| 有配音吗 | 用原片的声音（可换音色） | **TTS 合成**，配音时长就是时间根 |
| 产出 | 若干条结构相同、画面全新的片子 | 一条新片 |
| 人用的界面 | 工作台 | 编导台 |
| 命令 | `import` / `analyze` / `candidates` / `apply plans` / `export` | `script *` |

**两条线各有两种起点，起点不是模式**——同一条线进去之后干的是同一件事：

| | 有原片 | 没有原片 |
|---|---|---|
| **替换裂变** | `import <视频>` → 分析切分 → 逐镜换素材 | `blank` → 手动排位置、每个位置挑素材 |
| **脚本成片** | `script new` 建任务 → `script extract <参考片>` 提取台词 | `script new` → 直接写台词 |

**怎么选：先问「原来那个人的声音还要不要」**

这是两条线最根本的区别，也是最容易选错的地方：

| | **替换裂变** | **脚本成片** |
|---|---|---|
| 声音 | **用原片的声音** | **TTS 重新念** |
| 节奏 | 天然和原片一模一样 | 由配音时长决定，**和原片必然不同** |
| 台词 | 不能改（那是原片的音轨） | 随便改，本来就是你写的 |
| 产出 | 若干条结构相同、画面全新的片子 | 一条新片 |
| 命令 | `import` / `analyze` / `candidates` / `apply plans` / `export` | `script *` |

**人说「1:1 复刻」「节奏照着它来」的时候，多半要的是替换裂变** ——
只有用原片的声音，节奏才可能真的 1:1。走脚本成片的话，TTS 按自己的语速念，
成片长度和原片对不上是**结构性的**，不是调一调就能解决的（真机上长了 27%）。

**什么时候才该走脚本成片**：

- 台词要改（换卖点、换活动、换价格）
- 要换个人来念（原片主播的声音不能用）
- 压根没有原片，从一段话开始做

**拿不准就直接问用户一句**：「原来那条片子的声音还用吗？还是重新配音？」
——这一句问清楚，比什么判据都准。两条线的数据和命令是分开的，选错了要推倒重来。

替换裂变**没有原片的那种起点**叫空白任务（`blank`）：手动排几个位置、
每个位置挑一条素材拼起来。它和有原片时走的是同一套命令，只是**没有配音、
也没有字幕**（没有台词可念）。用户要「拼一条无口播的片子」时用它，
别跟脚本成片搞混——那条是有台词有配音的。

替换裂变有两层切分，别搞混：

| 术语 | 是什么 | 人嘴里的叫法 |
|---|---|---|
| **台词语义单元**（U） | 按台词语义切的段落。一段完整意思算一个，可能一句也可能几句 | 「分子」 |
| **视觉镜头**（S） | 单元内部的画面切换。一个单元通常含多个镜头 | 「原子」 |

**「分子」就是台词语义单元，「原子」就是视觉镜头**——界面上和人说话时都用
这两个词（空白任务那节的「加一个分子」说的就是加一个单元）。听到「分子」
不要以为是别的东西。

替换有三种：整段换掉（`whole`）、只换其中某几个镜头（`perShot`）、
保留原片（`keepOriginal`）。

## 全流程（替换裂变）

> 从零做一条新片的，不看这一节——直接跳到文档末尾的
> 「脚本成片（编导台）」。

**开工第一件事：体检。**

```bash
ishkafel doctor
```

它一次问完三件事：AI 凭据在不在、素材库登没登录、ffmpeg 有没有。
**不体检就往下走，你会在第二步栽**——`import` 不需要凭据，
所以它总能跑成功，给你一个「环境没问题」的假象，
等 `analyze` 炸的时候视频已经导进去、任务也建好了。

退 5 就是环境没配好：**把 stderr 那几句转给人去补，别重试**，
那些事只有人能做（比如 `miaoa auth login` 要跳浏览器）。

```bash
# 0. 看有哪些标签组（下一步要用它的 id）
ishkafel tag-groups

# 1. 建任务。标签组必须在这一步定
ishkafel import <视频路径> --tag-groups 396,365

# 2. 分析：抽音频 → ASR → 语义切分 → 镜头切点 → 打标
ishkafel analyze <task>

# 3. 看任务全貌，规划要换哪些
ishkafel task <task>

# 任务列表（短编号/id/名字/状态）。用户嘴里的任务是「#12」这种短编号，
# 所有 <task> 处直接给 #12 或 12 都认；对不上号先跑这条
ishkafel tasks

# 4. 逐个位置看候选（带上下文）。缺省按这一层的标签检索并自动收窄
#    （剔掉 0 条的和「实拍」这类命中全库九成、等于没筛的标签）；
#    --keyword 走画面描述语义搜；--page 翻页（每页 50，结果带 total）
ishkafel candidates <task> --unit 1 --shot 5
ishkafel candidates <task> --unit 1 --shot 5 --keyword 厨房喷洒清洁剂
ishkafel candidates <task> --unit 1 --shot 5 --page 2 --tag-mode and

# 5. 提交完整方案列表（--file 或直接管道进 stdin）。
#    提交即生效：方案会投影成任务的替换现状，供人审核
ishkafel apply plans <task> --file plans.json
echo '{"plans":[…]}' | ishkafel apply plans <task>

# 6. 导出（规格可选，缺省 1080P/30fps/推荐码率/H.264/mp4；
#    不给 --out 时落到 ~/Desktop/ishkafel-<task>；人在 GUI 设过换音色的话，
#    已生成的配音会自动带上，缺配音会被拦下点名）
ishkafel export <task> --out ~/Desktop/成片 \
  [--resolution 480|720|1080|1440|2160] [--fps 24|25|30|50|60] \
  [--bitrate recommended|higher|lower|<kbps>] [--codec h264|hevc] [--format mp4|mov]

# 6'. 或者交给剪映：写成一份工程，人在剪映里边看边切、接着精修
ishkafel jianying <task>
```

**`export` 和 `jianying` 是两个出口，不是一个的两种格式：**

| | `export` | `jianying` |
|---|---|---|
| 出什么 | 若干条 mp4，每条都定死了 | **一份**剪映工程 |
| 候选怎么办 | 组合成多条成片 | **全摆进去**，同一位置摞成多条轨 |
| 谁来定最终用哪条 | 你（在 apply plans 时就定了） | 人，在剪映里边看边切 |
| 什么时候用 | 人要的是能直接发的成片 | 人说「我自己再改改」「拖进剪映修」 |

剪映工程里的轨道从下往上是：**台词语义单元轨**（原片按 U 切开）、
**视觉镜头轨**（原片按 S 切开）、然后每个位置的第 N 个候选各占一条轨。上层盖下层，
所以打开看到的是第一候选；人把上面那条关掉，下面那条就露出来。
字幕是**文本轨**不是图，人能直接改字。

**不会替人打开剪映**——剪映没有给外部程序「打开指定草稿」的通道。
把草稿名告诉人，让他去剪映的「本地草稿」里找。剪映如果已经开着，
要重启它才会出现在列表里。

## 不用原片，从素材拼（空白任务）

**替换裂变的另一种起点**，不是另一条线：没有参考成片、也不需要台词与配音，
只是手动排几个位置、每个位置挑一条素材拼起来。**要台词和配音的走脚本成片**，
不是这里。

分子手动加、标签手动填，之后（候选、方案、导出）与上面完全同一条路：

```bash
ishkafel blank create --name 拼片A --tag-groups 1261   # 自带 4 个空分子
ishkafel blank tags <task> --unit 0 --tags 促单,痛点    # 标签必须在词表内；--tags 给空 = 清空
ishkafel blank add <task>                              # 加一个分子
ishkafel blank remove <task> --unit 4                  # 删一个（保底 4 个）
ishkafel candidates <task> --unit 0                    # 之后照旧
```

空白任务里每个分子都是整体替换：没有原始画面，`keepOriginal` 与 `perShot`
都不成立，方案里每个单元都要给 `whole` + material。`analyze` 对它无意义，
会直接拒绝。

### 一个位置只放一条素材不够用时：把它切开（底片）

上面那句「每个分子都是整体替换」有个出口。**整段塞进去一条素材，是这一段
最粗的用法**——素材里可能有四五个镜头，你只想要其中两个，或者想把第三个
换成别的。

这时把这一段**切开**：那条素材从此是这一段的「底片」，按它的画面切点划成
若干视觉镜头，每一镜都能再单独挑素材。手动加的插入段（有原片的任务里
`hasSource=false` 那些）同样适用。

```bash
ishkafel unit base <task> --unit 1        # 先问：底片是谁、能不能切、切了掉什么
ishkafel unit segment <task> --unit 1     # 切。之后 candidates/plan 照常按镜头来
ishkafel unit unpin <task> --unit 1       # 换一张底片（旧的镜头全部作废）
```

`unit base` 回的 JSON：

| 字段 | 含义 |
|---|---|
| `base.kind` | `material`（底片是挑来的素材）/ `original`（原片那一段）/ `none`（还没挑） |
| `pinned` | 底片固定过没有——真表示镜头是按它切出来的 |
| `shots` | 切出来几个镜头 |
| `canSegment` | 能不能切；不能时看 `blockedReason` |
| `segmentWouldDrop` | 切下去会掉什么：`otherCandidates`（多余的候选）、`shotPicks`（已挑的镜头替换） |
| `shotsTagged` | 这几镜里打过标的有几个。**没打就别急着按标签/画面搜**——检索键就是它们 |
| `baseSentenceCount` | 底片转写出几句（字幕从这一份取）。null = 还没转过，0 = 转过、这条素材没人说话 |
| `transcript` | 这一段的台词（转写接起来的）。它也是单元层打标的输入 |

三条要记住的规则：

- **切分要花时间也要花钱**（读一遍素材、灰区切点还要送云端复核），
  所以它是显式命令，挑完素材不会自动跑。先 `unit base` 看清楚再决定
- **底片只能有一张**。这一段选了三条素材本来能出三条变体，切下去就只剩
  被选中的那一条——这一段不再产出变体，变体只来自它内部各镜头的选择
- **到此为止**。底片切出来的第 N 镜换进来的那条素材，**不再**往下切分。
  一层底片 + 一层镜头，就这两层

切开之后这一段就是普通的镜头级替换：`candidates --unit 1 --shot 2`、
`plan` 里给 `perShot`，和有原片的任务完全一样。**字幕也有**——取自底片素材
自己的转写，坑位按素材内偏移算；某一镜里没转出话来（本来没人说、或者转写
没成）就是没有，那时用 `unit subtitle` 自己排。

**删任务**（不可逆，连素材、配音、预览产物一起走）：

```bash
ishkafel task-delete <task> --yes
```

不加 `--yes` 只会告诉你要删的是什么、不会真删。

**复制任务**（同一条原片想试两套完全不同的替换思路时用）：

```bash
ishkafel task-copy <task>                      # 名字自动叫「原名 的副本」
ishkafel task-copy <task> --name "B 路线"       # 自己起名
```

切分、标签、已挑的素材、配乐、字幕、配音全都照搬，**两条任务此后完全隔离**
——改一条不动另一条，删一条也不影响另一条（素材、配音、人声轨会各存一份，
返回的 `bytesCopied` 就是这一下占的盘）。

不抄的三样：导出历史、AI 用量、首次可用耗时——副本没导过片子、没花过钱、
也没让人等过，抄过去等于重复计账。**还在分析的任务不给复制**（那时产物
只有一半）。

任何一步都可以停下来交给人：

```bash
ishkafel open <task>    # 把 app 弹出来，落到这个任务的工作台
```

**输出约定**：成功时结果是一行 JSON 走 stdout（例外：`open`/`review` 只在
stderr 给一句状态、`skill` 输出 Markdown）；进度和失败原因走 stderr，
是能直接照做的中文。退出码：

| 码 | 含义 | 你该做什么 |
|---|---|---|
| 0 | 成功 | 继续 |
| 2 | 用法/参数错误 | 改命令重发 |
| 3 | 找不到（任务/单元/候选） | 核对 id 后重发 |
| 4 | 被别人锁着（人在操作） | 等人退出再试 |
| 5 | 环境未就绪（缺凭据/miaoa 不可用/app 没装） | 把 stderr 的话转给人去补环境，别重试 |
| 1 | 其他运行失败 | 看 stderr 决定 |

**多环境**：数据目录默认与 GUI 一致；`--data-dir <目录>` 或环境变量
`ISHKAFEL_DATA_DIR` 可换。

**app 装在哪，一般不用你管**：命令行工具本身就装在 app 里面，
所以任何要拉起界面的命令（`open`、`review`、`ui new-task`、
以及带 `--visual` 的）都能自己找到它，**app 关着也能拉起来**。

只有一种情况要你出手：这个命令行工具被单独拷到别处了。那时报错会直接
告诉你怎么办：

```bash
export ISHKAFEL_APP=/path/to/ishkafel.app
```

路径去问用户要。

## 两种模式：人在不在旁边看着

这不是技术开关，是两种完全不同的场景。**开工前先弄清人要哪一种**，
然后贯穿整个会话——别中途换。

**静默（默认）**：人不在场。软件被你调起来干活，人回头看结果或直接看成片。
不弹窗、不导航、不等界面——快就是好。

### 不要用 Computer Use / 截图点击

界面上人能做的事，**都有对应的命令**。看到「要打开某个页面、点某个按钮、
填某个表单」时，不要去截图找坐标点击——那样慢、脆、而且人看不出你在干嘛。

这条尤其针对**新建任务**：不要以为「建任务是界面上的事、只能人来点」。
`ishkafel ui new-task` 就会让界面当着人的面把向导打开、填上、创建。

真的遇到没有对应命令的界面操作，**说出来让用户补**，别绕过去。

**可视（`--visual` 或 `ISHKAFEL_VISUAL=1`）**：人在场，而且他要**看着**。
就像站在实习生旁边：

- 软件**自己弹出来**，你开哪个模块界面就切到哪个模块
- 你动哪一行、哪一镜、哪张卡，界面就把它滚到眼前、把那个面板打开——
  跟人自己点开时是同一个面板
- 这期间界面是**只读**的：人不能操作，但**随时能在你这头喊停**
  （Ctrl+C 你就立刻放手，界面马上恢复可操作）
- 节奏由界面定：它真的展示完一步（滚动停下、面板展开）才回执，你收到
  才走下一步。**不要自己猜时间等几百毫秒**

**播报条上分三类，人一眼分得开**——你不用管怎么发（软件自己按场景发），
但要知道它们对人的意义不一样：

| | 长什么样 | 什么时候 |
|---|---|---|
| 进度 | ▸ 灰白 | 「正在给 U2S4 挑素材」——你走到哪儿了 |
| 判断 | 💡 蓝 | 「标签命中 5318 条太宽，改用画面描述再搜一轮」——**你为什么改主意** |
| 发现问题 | ⚠ 橙、加粗、不变淡 | 「有 2 条素材画面上烧着字」——人可能要当场喊停 |

**判断那一类最值钱**：人肯把花钱的活交给静默模式，靠的正是「我看懂过它
是怎么想的」。发现问题那一类不会被后面的流水账挤掉——人走开一会儿回来，
要找的就是它。

**支持可视的命令：凡是会改数据的都支持**——`import`、`analyze`、
`candidates`、`apply`（plans / segment / tags）、`export`、`jianying`、
`review drop/keep`、`voice generate`、`subtitle`、`bgm`、
`script extract`、`script voice`、`script voice-file`、`script shots`、
`script tag-ref`、`script apply`（全部子类）、`script export`、
`script jianying`、`unit`（add / remove / move / tags / audio / subtitle）。

只读的命令（`show`、`tasks`、`status`、`frames`、`peek`、`todo`…）
没有可视一说——它们什么都不改，界面也就没什么好跟的。
**人说这些话，都是要可视**（他不会说 `--visual`，那是你的事）：

> 「用可视化模式」「可视化」「我看着」「你做给我看」「我在旁边看着你做」
> 「当着我的面做」「你把这个视频复刻一版，我看着」

对着这份手册干活的人多半是**编导或剪辑**，不是工程师。他不会告诉你敲哪条
命令、设哪个环境变量——**那些是你自己该解决的**。他只会说要做成什么样、
以及他在不在旁边看。

**挑素材和提交方案这两步最该开可视**：那是真正在做决策的地方，
成片长什么样就是这两步定的。

**新建任务在可视模式下要用 `ui new-task`**：

```bash
# 当着人的面：软件弹出来 → 向导打开 → 来源和标签组填上 → 点创建 → 进任务
ishkafel ui new-task --mode script --tag-groups 1261,1262
ishkafel ui new-task --mode replace --tag-groups 1261 --file ~/原片.mp4
ishkafel ui new-task --mode blank  --tag-groups 1261
```

`--mode` 是**两条线四种起点**里的三种：`replace`（替换裂变，要给原片）、
`blank`（替换裂变但不用原片）、`script`（脚本成片）。脚本成片的第四种起点
「从参考片提取台词」发生在编导台里，不在这一步。
（`renew` 是 `replace` 的旧名，仍然认，但别再用。）
参数不合格时**不会弹向导**——让人看着窗口弹出来又关掉，比不弹更糟。

**建完的下一步不用腾锁**：界面这会儿停在新任务上占着写锁，但这不用你管
——下一条命令撞上它会**自动请界面让位，而人留在那一页看着**
（这正是可视模式要的）。直接往下走：

```bash
ishkafel script extract <任务> ~/参考片.mp4
```

**别主动调 `ui tasks` 去腾锁。** 它会把界面支开、退回任务列表——
可视化现场就此关掉，而且你后面每一步人都看不见。真机上发生过：Agent
为了拿写锁先支开了界面，接着二十句配音全程在任务列表页上以文字滚过，
一格画面都没出现。要把界面叫回来用 `ui open`。

人不在场时用 `script new` / `blank create` / `import` 更快，
那几条在后台直接建好。**但界面开着的话，列表会自己刷新出来**——
不会再出现「命令说建好了、界面上什么都没有」。

### 开工前先确认现场

可视模式下，**每一步开工前都要先弄清「界面此刻在哪一页、这一步该在哪一页
看」**。命令自己会做这件事：走每一步时看一眼界面在哪，不在这一页就先把它
带过去，已经在就什么都不做（不会把页面销毁重建）。

所以**被人打断之后接着干，不用特意做什么**——下一条命令会自己把界面叫回
现场。人在打断的间隙多半已经把界面切走了（退到列表、开了别的任务），
这一步就是为它准备的。

要显式把人带到某一页时用：

```bash
ishkafel ui open <任务>                    # 按任务类型进编导台/工作台
ishkafel ui open <任务> --module review    # 指定去哪个模块
```

它会等界面**真的落到那一页**再返回；已经在那一页就直接返回，不折腾。

**没有这一步，可视化就是一句空话**：播报照念「正在给第 10 句配音
（10/20）」，人却对着任务列表，二十句一格都看不见。

**人中途插手了怎么办**：他会在界面上按「我来接手」，你的写入随即被拒
（退出码 4）。这时**停下来问他**，别硬重试——他改了什么只有他知道。

## 语义切分和打标可以你自己做

第 2 步默认烧内置 API。加 `--external` 就把其中几步交给你——**这不是省钱的
开关，是让你能用上你的判断**：内置的那两步只看得到文字和时间，你能真的去看画面。

```bash
ishkafel analyze <task> --external=segment,tag
```

analyze 跑到该你做的地方就停下来，输出一件**待办**：它自带 `input`（你要的
全部输入）、`rules`（会被卡住的硬约束）、`shape`（回填格式的样例）、
`apply`（做完执行哪条命令）。照着做，然后：

```bash
ishkafel apply segment <task> --file seg.json    # 回填切分，接着吐下一件待办
ishkafel apply tags    <task> --file tags.json   # 回填标签
ishkafel todo <task>                             # 待办输出丢了，取回来
```

能外包的只有 `segment`（语义切分）和 `tag`（打标）。**ASR 不能**——它的
时间戳偏 200ms 就毁掉整条链，切分错位、镜头对不上，而且不报错，一路静默
到看成片才发现。写别的名字会直接报错，不会当作没写。

两条会被拦下来的硬约束，先知道比事后改快：

- **切分必须首尾相接、覆盖全部句子。** 用 `fromSentence`/`toSentence` 句子
  下标（含两端），别给台词文本——文本由句子拼出来，那是 ASR 的产出，不归你改
- **标签必须逐字命中 `vocabulary`。** 「厨房场景」和「厨房情景」在检索时是
  两回事，写错的一律拒收，不做近似匹配

**镜头标签必须看过画面再打。** 待办里给了 `sourcePath` 和每个镜头的
`sampleAtSec`（取的是镜头中点，两端常常正踩在转场上，抽出来是糊的）：

```bash
ffmpeg -ss <sampleAtSec> -i <sourcePath> -frames:v 1 -vf scale=180:-1 shot.jpg
```

51 个镜头就抽 51 张，拼成几张联系表一次看完，比一张一张看快得多。
光凭台词和时间戳猜画面里有什么，打出来的标签会把后面的检索带偏。

一批只错一条也整批不落——错误会一次全报出来，改完重交即可。

## 挑素材：这一节决定成片能不能用

### ① 标签组选错，后面全废

标签组是**按企业分的**。miaoa 当前企业不对 → `tag-groups` 列出来的是别的企业
的 → 打标没有受控词表 → 挑素材时没有标签可用。**这条链上没有任何一步会报错**。

`import` 时如果不给 `--tag-groups`，会警告但仍然建任务——那条任务是残废的，
别接着用。

### ② 必须看前后，否则「每个都对，连起来不对」

`candidates` 返回的 `context`，**用它们**。带 `--shot`（镜头替换）时最全：

```json
{
  "slotMs": 2867,                    // 这个坑位多长
  "unitTranscript": "它虽然贵，但…",   // 这一段在讲什么
  "description": "向微波炉内壁喷洒清洁剂…",
  "previous": {"description": "手持喷雾瓶向镜头展示", "pickedMaterialIds": []},
  "next":     {"description": "台面上展示多瓶喷雾",   "pickedMaterialIds": [116719]}
}
```

不带 `--shot`（整体替换，空白任务只有这种）时 context 只有
`unitIndex` / `slotMs` / `unitTranscript` / `unitTags`——没有镜头级
描述和前后文，判断依据主要是台词和候选自己的 `description`。

**画面描述语义搜（`--keyword`）才是主力，标签是辅助。**

素材库**按标签检索不做相关性排序**，返回的是 id 最新的那几十条。命中几百条时
还看得过去，命中上万条时前几页就是随机取样——真机上一个 35 镜的任务每一镜都命中
一万多条，要「女孩在书桌前情绪激动诉说」，首条给的是「户外街道上女士与男孩
并排走着交谈」。

所以命中数一超出四页，`candidates` 会**自动改用这一镜的画面描述做语义检索**，
并在 `searchFallback` 字段里说明换了什么、为什么换。看到这个字段就知道
标签这条路在这一镜没用。

**keyword 怎么写，比写不写更要紧。** 同一个镜头换个说法，候选数能差一百倍：

- 直接拿镜头 `description` 的前半段去搜（「夜晚，在室内的书桌前，女孩坐在
  桌前情绪激动地向身旁站立的男性诉说自己长痘是因为…」）→ 只回来 **1 条**
- 改成一句**画面短语**（「阳台晾衣架前手持消毒液产品特写」）→ 回来 **994 条**，
  首条跟原镜几乎一模一样

写法：**场景 + 主体 + 动作**，十来个字，别带因果、别带台词内容、别带情绪解释。
description 是给人读的完整描述，不是检索词。

**只回来个位数就是措辞太窄**，换个说法再搜一次，别拿这一两条硬凑——
那一镜三条方案就没差异了。

**要换掉原片那批画面就用 `--exclude-projects`**：语义搜越准，搜出来越是
原项目自己拍的（跟原镜最像的当然是原片素材）。真机上那一镜前五条全是原项目。

```bash
ishkafel candidates <task> --unit 0 --shot 0 --exclude-projects 107
```

它会边搜边排，一页排空了自动往后翻（最多五页），并如实告诉你排掉了多少条
（`excludedCount`）、翻了几页（`pagesFetched`）。每条候选都带 `projectId`，
自己核对。项目 id 在 `ishkafel task <任务>` 的 project 字段里；原片没绑项目时，
先不带这个参数搜一次，看前几条的 `projectId` 是哪个。

人挑素材时是有整体感的——知道这里是开箱、那里是演示效果，所以不会在
「擦冰箱」后面接一个同类空镜。**你要做同样的事**：读台词知道这一段在说什么，
看前后镜头避免雷同或跳脱。

只按标签命中数挑，会得到一批**每一个都合规、连起来很怪**的片子。

### ③ 同一批素材常常几乎一样

素材库里经常是：1~5 号几乎一模一样（只有微小变化），6~10 又是另一批微调版。

**先看图再定**。`candidates` 给了 `thumbnailUrl`，读它。把明显同批的看作一个，
组方案时在**不同批之间**取，否则导出几十条片子看起来是同一条——而矩阵导出
的全部价值就在于变体之间有可见差异。

### ④ 素材画面上可能本来就烧着字

这是**只有看图才发现得了、而且会毁掉整片**的一类。真机撞到过：素材库给的
画面描述写「成人给小孩按摩额头」，画面底部烧着别家品牌的「冰冰凉凉的好舒服呀」。
换上它之后我们还要再烧一行台词字幕——两层字叠在一起、内容还毫不相干，
这条片子就废了。**描述里一个字都看不出来**。

`apply` 收下方案时会挨条看一眼（素材已经落到本地就抽一帧看），结果在两处：

```bash
# 提交那一刻就会告诉你是哪几条
# 三态分开：有问题 / 都干净 / 没看成。**别用 `.burnedText // "干净"`**——
# jq 的 `//` 正是「null 就用右边那个」，那会把「没看成」显示成「干净」
ishkafel apply plans <任务> --file plan.json | jq -r '
  if .burnedText then .burnedText
  elif .materials.frameUnchecked > 0
  then "有 \(.materials.frameUnchecked) 条没看成，别当画面干净"
  else "这批素材画面都干净" end'

# 事后再看
# 逐条看：有字的、干净的、没看成的分开数——**「没看成」不是「干净」**
ishkafel task <任务> --json | jq -r '.pickedMaterials.items[]
  | if .burnedText == null then "\(.id)：没看成，别当干净"
    elif (.burnedText|length) == 0 then "\(.id)：画面干净"
    else "\(.id)：烧着「\(.burnedText|join("、"))」" end'
```

**`burnedText` 为 `null` 是「没看成」，不是「画面干净」**——空数组才是干净。
没看成通常是素材还没落到本地，或这台机器没配方舟凭据。别把 null 当成放行。

**没看成怎么办：把素材拉到本地，再原样重提一遍。**
刚挑好的素材多半还没下载，所以第一次提交时画面自查会整批跳过——
`apply shots` 的输出里会点名是哪几条（`uncheckedMaterials`）。

```bash
# 1）把它们拉到本地
ishkafel script peek <任务> --materials 105475,114798,108973
# 2）把刚才那份提交**原样再提一次**——这次才会真的抽头中尾三帧看图
ishkafel script apply shots <任务> --file p.json
```

**别省这一步。** 真机上正是这一轮才查出有条素材底部烧着别的片子的台词，
位置恰好是我们要烧字幕的地方——照第一轮直接导出，交付的就是两层字打架
的废片。

有烧字的就换一条：那一段重新 `ishkafel candidates` 挑，别硬用。

### ⑤ 整体替换的那几段，成片里没有台词字幕

两种替换模式在这件事上不一样，而这个差别在界面上和输出里都曾经看不见：

| | 画面 | 台词字幕 |
|---|---|---|
| **镜头替换** | 变速对齐回原坑位 | **重渲上去**（原片字幕烧在被换掉的画面里，不重渲就没字了） |
| **整体替换** | 原样接上、时长随候选 | **没有**——和原坑位对不齐，按原片时间戳算的字幕烧不上去 |
| 保留原片 | 不动 | 还烧在原画面上 |

```bash
ishkafel task <任务> --json | jq -r '.subtitleCoverage.note // "每一段都有字幕"'
```

**这件事决定了上一节那条烧字警告有多严重**：
- 这一段会烧台词字幕 → 素材自带的字 + 我们烧的字 = **两层字打架，片子废**
- 这一段不烧 → 只是片子里放着别人的文案和免责声明，不算废，但也交不出去

要那几段也有字幕，改用镜头替换。

### ⑥ 产品露出的镜头不能跨品牌换

**不是所有镜头都能跨项目挑**，要分两类：

- **产品露出镜头**（手持产品讲解、倒液体、检测报告、开箱、直播间货架）
  → 画面里的产品必须还是本品牌
- **场景镜头**（人物痛点、生活情景、空镜）
  → 随便哪个项目拍的都行，只要画面里没有别家产品露出

台词说「滴露新款消毒液」而画面是若也洗发水直播间（背景还有 logo 墙），
片子自己打自己的脸。2026-08-28 真机上就这样交付过一条成片。

**`--exclude-projects` 反而放大这个风险**：排掉原片项目之后，语义检索会把
最像的别家品牌素材顶上来——那个参数只懂项目 id，不懂品牌。

`apply` 收下方案时会挨条看画面里露的是谁家产品（和看烧字是同一次调用）：

```bash
# 提交那一刻就会告诉你品牌打不打架
ishkafel apply plans <任务> --file plan.json | jq -r '
  if .brandConflict then .brandConflict
  elif .materials.frameUnchecked > 0
  then "有 \(.materials.frameUnchecked) 条没看成，品牌对不对不知道"
  else "品牌一致" end'

# 事后再看每条素材露的是什么牌子
ishkafel task <任务> --json | jq -r '.pickedMaterials.items[] | select(.productBrand) | "\(.id)：\(.productBrand)"'
```

**`productBrand` 为 null 有两种含义**，看 `framesSeen` 分辨：整份检查没做过时
它当然是 null；`framesSeen` 有值（说明看过了）还是 null，才表示这一镜画面里
没有产品露出。

`framesSeen` 还告诉你这个结论有多硬：**1 帧看不全**——产品可能只在素材的某
几秒里出现（真机上有条素材首帧是一排滴露瓶、中段是微波炉内部，只看中段就
记成了「无产品露出」）。界面挑素材那一刻素材本体还没下、只有一张首帧图，
所以是 1；`apply` 提交时素材已在本地，会抽头中尾三帧再看一次顶掉它。

**两条判据是互补的**，`apply` 的 `brandConflict` 两条都查：

- 挑的素材**之间**出现了两个牌子 → 一条片子里不可能同时是两个牌子
- 挑的素材**全是别家的** → 彼此不打架，但整条跑到别家去了。
  这一条的参照是**原片自己的产品露出镜头**（分析打标时顺手记的），
  用 `ishkafel task <任务> --json | jq -r '[.units[].shots[].productBrand] | map(select(.)) | .[0]'`
  能看到原片露的是什么牌子。老任务（打标那会儿还没记品牌）看不到，
  那时只有第一条判据管用。

发现品牌打架就换：那几镜重新 `ishkafel candidates` 挑，别硬用。

### ⑦ 时长差异会变成变速

镜头替换的候选比坑位长就加速、短就放慢，**倍率不设限制**——3 秒坑位塞
10 秒素材就是 3.3× 快放，照常导出。但倍率大了观感就是快进/慢动作。

**加 `--probe` 就能知道选它会变速多少**：

```bash
ishkafel candidates <task> --unit 3 --shot 2 --probe
```

每条候选会多出 `durationMs` 和 `speedIfPicked`（塞进这个坑位的倍率）。
**1.0 附近最自然**；到 2 以上是明显快进，0.5 以下是明显慢动作。
**每一镜都要看这个数**：软件不截素材，长素材配短坑位就是十几二十倍快放，
不看就是在赌。

默认不探是因为一页 50 条各跑一次 ffprobe，慢到人以为卡死了。
**要下判断的那一镜才加 `--probe`**，不必每次都带。

**视觉镜头替换一律整条变速铺满原镜头时长——所以要挑长度对得上的**

原片的快切镜头只有 0.4~1 秒，而素材库里的分镜普遍 4~30 秒。真机上一条
34 镜的片子，102 条候选里有 **74 条素材比坑位长 3 倍以上**，最夸张的
24 倍（19 秒素材配 0.8 秒坑位）。

软件**不会替你截**：选中的那条素材整条压进原镜头的时长里，长多少倍就是
几倍快放。这是产品定的方案（画面完整比倍速自然更重要），代价由你在挑的
时候看住——`candidates --probe` 里的 `speedIfPicked` 就是那个代价：

```json
{"id": 65071, "durationMs": 20000, "speedIfPicked": 25.0,
 "trimRange": {"minStartMs": 0, "maxStartMs": 19500}}
```

**长度就是硬指标**：同样像的两条，挑 `speedIfPicked` 靠近 1.0 的那条。
两位数的倍率意味着这一镜在成片里是一道闪光，人一眼就看出来。

素材开头有转场或黑帧、想从中间开始用，提交方案时给 `trimStarts`：

```json
{"mode":"perShot","shots":{"6":115813},"trimStarts":{"6":6783}}
```

给了起点也不截：从那儿到素材结尾的部分整条铺满坑位。所以起点往后挪一截，
剩下的素材变少、倍速跟着降——挪到 `maxStartMs` 时剩下的正好一个坑位，
倍速回到 1.0。

**提交完方案，确认倍速算出来了**：

```bash
ishkafel task <task>   # 看 pickedMaterials.withDuration
```

倍速要靠素材时长才算得出来。`withDuration` 明显小于 `count` 的话，
那些镜头的倍速软件也不知道，只能到导出那一步才现算。

**光看数字不够的时候就亲眼看**：

```bash
ishkafel peek --video <素材或成片路径> --ats 0,30000,70000
```

抽帧到本地，路径给你，直接打开看图。看候选长什么样、看导出来的成片对不对，
都用它——**别把「文件存在、大小合理」当成验过了**。

## 你能拿到的信息，和坐在软件前的人一样多

这是这套工具的设计原则，也是你该有的姿态：

> 想还原一个熟手的操作，先得让你**拥有他拥有的全部信息**。
> 人给你派活的时候，你才能拿着足够的信息跟他的目标对齐。

所以：**凡是人在界面上看得见的，你都能拿到本地文件**。

| 人在界面上 | 你用什么拿 |
|---|---|
| 点开某条候选看看 | `ishkafel peek <任务> --materials <id,id>` → `framePath` |
| 看这条候选够不够长、会不会变速 | `ishkafel candidates … --probe` → `durationMs` / `speedIfPicked` |
| 看原片这一镜长什么样 | `candidates` 的**顶层** `sourceFramePath`（不在 `context` 里）——要复刻的就是这一帧 |
| 看导出来的成片对不对 | `ishkafel peek --video <成片> --ats 0,30000,70000` |
| 看这一镜的画面描述、标签、前后文 | `candidates` 的 `context` |

**看图不是锦上添花，是判断的主要依据。** 画面里的很多东西（光线、动作、
镜头运动、素材自带的字）文字描述不出来，而它们恰恰决定「这一镜对不对」。

**别把「文件存在、大小合理」当成验过了。** 导完至少抽三帧看一眼——
开头、中间、结尾。一帧就能同时验完「画面是不是我挑的那条」和
「字幕跟台词对不对上」。

### 素材画面里自带字幕——最容易漏、后果最重

素材库里不少分镜**画面底部烧着别家品牌的字**，而画面描述里一个字都看不出来。
真机上撞过：描述写「成人双手轻柔按摩小孩的额头，小孩闭眼享受」，
peek 出来一看底部烧着「冰冰凉凉的好舒服呀」。

这不是不好看，是**片子直接废**——我们再往上烧一行台词字幕，成片上就是
两套字幕打架，而且那句话跟本片台词毫无关系。

**只有看图能发现。** `--probe` 看不出来，描述里也没有。所以挑完关键镜头
一定要 `peek` 一眼。

发现了有两条路：

```bash
# 一：换掉这条素材（最干净）
# 二：把字幕改成能遮挡的样式——软件一直有这个能力
ishkafel subtitle <task> --preset blurBox
```

四个预设里，**只有两个能遮挡**：

| 预设 | 遮不遮得住 |
|---|---|
| `whiteOutline`（默认，白字黑描边） | **盖不住**，原字幕从描边缝里透出来 |
| `yellowOutline`（黄字黑描边） | 同样盖不住 |
| `whiteBox`（白字 + 半透明黑底条） | 能盖住 |
| `blurBox`（毛玻璃：字幕背后那块画面被局部模糊） | 能盖住，观感更自然 |

**但遮挡有边界**：底条/毛玻璃的宽窄是按**新字幕的文本框**算的。原字幕比
新字幕长、或者位置更高时仍然盖不全——那种素材只能换掉。所以遮挡是补救，
不是万能。

### 收拾自己造的东西

跑久了盘上会攒下几个 G——素材、切片、抽帧、导出中间产物，全是你造的。
删过任务之后，它们就成了没人认领的孤儿。

```bash
ishkafel clean          # 先看会删什么，不动手
ishkafel clean --yes    # 确认没问题再真删
```

**只删没主的**：活着的任务的东西一个都不碰。默认只报不删——删了没法撤回。

### 配乐：人能铺，你也能铺

配乐是**进成片**的东西，不是装饰。界面上人给一段单元铺曲子、改区间、
调音量、删掉——这一套你也有：

```bash
ishkafel script bgm-candidates <task> --keyword 轻快   # 有哪些曲子
ishkafel bgm <task> --from 0 --to 2 --materials 7,8   # 给 U1~U3 铺
ishkafel bgm <task> --from 0 --volume 0.3             # 调这一段的音量
ishkafel bgm <task> --from 0 --remove                 # 删掉这一段
ishkafel bgm <task>                                   # 看现在铺了什么
```

**一段选好几首是「互为备选」，不是叠着放**：导出多条时按变体轮流用
（一段选 4 首、导 6 条，就是 A/B/C/D/A/B）。总条数只由画面替换决定，
配乐不做乘法。

### 台词语义单元这一层：加、删、调顺序、手填标签

人在工作台左栏能做的这四件事，你也都能做。**两种任务都适用**——有原片的
（替换裂变）和没原片的（拼片）。

```bash
ishkafel unit add <task>                        # 在末尾加一个单元
ishkafel unit remove <task> --unit 5            # 删掉第 6 个
ishkafel unit move <task> --unit 4 --to 0       # 把 U5 挪到第一位
ishkafel unit tags <task> --unit 5 --tags 促单,痛点   # 手填标签
```

**加单元是在参考片的骨架上「加戏」**。参考片决定了这条片子的结构，但它不见得
把要说的都说了——原片没讲到的卖点、更狠的片尾促单、开头的钩子，都靠加单元。
加出来的那个**原片里没有它**（`hasSource: false`），所以：

- **成片会比原片长**，不去挤原片已有的段落（挤时间等于把原片的某句话截掉，
  那是在拆骨架）
- 只能接在**末尾**。想让它排到前面，加完用 `unit move`
- **它没有台词**，模型没有任何东西可以据以打标——所以必须你用 `unit tags`
  手填。不填的话它永远搜不出素材，只是个挂着「待填」的空壳
- **必须给它挑素材**。原片里没有这一段，不挑就是真的缺一段；没挑就导出会被
  拦下并点名，不会拿黑帧顶上

**`move` 的含义是「列表顺序就是成片顺序」**。把 U2 挪到第一位，成片里它就
先播；这一段的台词、原声、字幕整句跟着搬，导出时原声按新顺序重剪。挑给它的
素材、给它配的音、盖在它上面的配乐也一起搬——你不用自己去对下标。

**只有一处要留神**：配乐是按**连续几段**铺的，把中间某一段挪走会打断它。
这时命令会在 stderr 说一句，去 `ishkafel bgm <task>` 复核那一段盖的范围。

`unit remove` 只删**手动加的**单元。分析切出来的删不掉——删掉等于把原片少放
一段，那是另一件事，这个入口不做。

### 视觉镜头替换：放素材自己的哪一路声音

镜头替换换的是**画面**，那一段的口播照旧来自原片。素材自己的声音默认丢掉，
但常常正是要的东西——所以是**四选一**，不是「要/不要」：

| 档位 | 放的是什么 | 什么时候用 |
|---|---|---|
| `none` | 不放（默认） | 只要原片这一段的声音 |
| `vocals` | 素材里说话的那一路 | 要素材里那句话 |
| `background` | 素材的现场音（说话声被分掉） | 要水声、喷雾声、环境感 |
| `original` | 原样整条，不分离 | 两样都要 |

```bash
ishkafel unit audio <task> --audio background --volume 0.25       # 全片打底
ishkafel unit audio <task> --unit 2 --shot 3 --audio vocals       # 这一镜单独选
ishkafel unit audio <task> --unit 2 --shot 3 --audio follow       # 改回跟随全片
```

**`vocals` 和 `background` 要先把素材分成两路**（跟给原片分人声是同一套工具，
一条素材十几秒，分完按素材缓存、不会重跑）。**分不出来就直接失败并点名是哪一镜**
——不会悄悄退回原声。这是有意的：你选 `background` 正是因为素材自带口播，
悄悄放原声等于两个人同时讲话，而你要把片子导出来听一遍才可能发现。

**`follow`（跟随全片）和 `none`（这一镜不播）不是一回事**：全片放原声时，
跟随等于放，而 `none` 是要这一镜真的闭嘴。

**新建的任务全片打底是 `original`（原声）**；2026-09-10 之前建的任务仍是
`none`，那是有意的——升级一版不该让旧任务导出来的片子突然多一层声音。

### 同一镜的另一层：原片这一段自己放哪一路

被替换掉的那一镜，声音有**两层**：上面那层是顶上来的素材，这一层是**原片
这一段自己的**。两层各选各的，最后混在一起——「原片的口播 + 素材的现场音」
这种组合就是这么搭出来的。

档位同一套（`none` / `vocals` / `background` / `original`），外加两个状态词：

| 值 | 意思 |
|---|---|
| `auto` | 全片这一层的默认：原混音照播，这一格铺了配乐就自动换成纯人声 |
| `follow` | 镜头这一层：跟随全片 |

```bash
ishkafel unit source-audio <task> --audio vocals                  # 全片打底
ishkafel unit source-audio <task> --unit 2 --shot 3 --audio none  # 这一镜不放原片声音
ishkafel unit source-audio <task> --unit 2 --shot 3 --audio follow # 改回跟随全片
ishkafel unit source-audio <task> --audio auto                    # 全片改回自动
```

三件要留神的：

- **只对换过素材的镜头生效**。没换素材的镜头照旧走自动那条路，在那种镜头上
  设了也不起作用（界面上连控件都不出现）。
- **`vocals` / `background` 用的是原片那一次分离的产物**。没有的话导出会在
  进门口被拦下，跑 `ishkafel analyze <task>` 补一份。
- **你选了什么就是什么**。手选过之后，「铺了配乐就换纯人声」那条自动规则
  不再插手——哪怕两层背景音叠在一起，那也是你的决定。

**默认全片 `none`**。挑档之前先看一眼素材的 `voiceover` 字段：非空说明它自己
有话说，这时选 `original` 或 `vocals` 会和你的台词打架，多半该选 `background`。

### 标签可以手改，改过的不再被自动重打

台词语义单元和视觉镜头的标签，人在属性栏里能直接改（只从这条任务的标签组里
选——标签是搜素材的检索键，词表外的词一个素材都搜不出来）。你走 `apply tags`
回填也是同一条路。

**手改过的标签会标上「人改过」，此后重新打标一律跳过它。** 不这样的话，人刚
照着画面做的判断会被一个后台步骤盖掉，而且不问一声——他不会想到是被盖了，
只会觉得「改了没生效」。

任务 JSON 里能看出来：单元和镜头上的 `tagsHandpicked` 为真就是人改过的。
**你要让模型重新接管，得先把手改清掉**，光跑打标是不会动它的。

顺带一提：**改标签不会自动重搜素材**。之前搜出来的候选是按旧标签搜的，
标签改了就该去 `ishkafel candidates` 重搜一次——软件只提醒，不替人做主，
因为重搜会冲掉他已经挑好的。

### 换了素材的镜头，字幕是重烧上去的——可以改

原片的字**烧在像素里**，读不出也抠不掉。所以换掉一个镜头的画面之后，那一段的
字跟着旧画面一起没了，必须重新烧一份贴回去。依据是 ASR 的**词级时间戳**：
一个字的读音中点落在哪个镜头的区间里，那个字就归哪一镜。

**没换素材的镜头不重烧**（原片自己的字还在），**整体替换的段落不烧字幕**
（时长跟候选走、和原坑位对不齐）。

**但「哪里断句好看」是编导的判断，规则算不对**。真机上撞到过：S1、S2 都换了
素材，「了」这个字的声音落在 S2，于是 S2 的字幕就以一个孤零零的「了」开头——
ASR 没错、切点也没错，只是没人能替编导决定这个字归哪句。

所以字幕可以手改：

```bash
ishkafel unit subtitle <task> --unit 1 --shot 2 --text "李斯特菌|沙门氏菌的游乐场"
ishkafel unit subtitle <task> --unit 1 --shot 2 --text ""      # 这一镜不要字幕
ishkafel unit subtitle <task> --unit 1 --shot 2 --auto         # 改回按 ASR 自动算
```

`--text` 用 `|` 分段，时间在这一镜的坑位内平均分（要精确到毫秒就去界面上调）。

**改的是字幕，不是台词。** 单元的 `transcript` 一个字不动——打标、检索、
换音色照旧用它。任务 JSON 里 `subtitleTrack` 记的就是手改过的那些坑位，
没改过的坑位不在里面（导出时现算）。

**一镜挑了几条候选，几条共用同一份字幕**：口播是同一句，只有画面不同。

### 换音色：人能换，你也能换

替换裂变默认用原片的声音，但**可以换成别的音色**（人在工作台上就是这么做的）：

```bash
ishkafel voices                                  # 有哪些音色
ishkafel voice <task> --units 0,2 --voice <音色 id>   # 只定方案，不合成
ishkafel voice generate <task>                   # 真正合成，按字符计费
```

**选和生成是分开的**：选是即时的，合成要走云端、每句几秒。人往往先把几句都
定好再统一生成——你也照这个来。

**只选不生成，导出会被拦下**（那是一道有意的拦截：选了音色却还在放原声，
成片就是前后两个人在说话）。`voice generate` 失败的句子会点名，
重跑同一条命令只补那几句。

`--voice` 给空串就是把这几句改回原声。

### 换音色时，原声怎么念的会被学过去

这条线换音色不是「照着文本念一遍」。软件会：

1. **听原声**那一段（能听音频的模型直接听）
2. 写出「这段是怎么念的」，并转成一句给合成模型的语音指令
   （形如「用急促、有压迫感的语气快速催促观众，重音落在价格上」）
3. 同时客观测量语速、停顿、重音
4. 让克隆音色照这句指令念
5. **探路两次**：第一次不带语速，看这个音色自然念要多久；对不上坑位
   就算出语速让它重念一遍——比事后把音频拉伸自然得多

所以换音色出来的东西会带着原主播的情绪走向，不是平铺直叙。

**说准一点**：这是「AI 听完写成一句话，让 TTS 照这句话念」，不是声学层面的
逐帧情感迁移。效果取决于 TTS 对那句指令的理解，个别句子可能不到位——
人说「这句念得不对」时，那是可以重新生成的。

### 人说「这一镜不对」的时候

别急着换个关键词重搜。先把那一镜和候选都调出来看：

```bash
ishkafel peek <任务> --materials <你给它挑的那条 id>
```

原片那一帧不用另外抽——`candidates` 的 `sourceFramePath` 就是它。
两张图摆在一起，多半一眼就知道差在哪：是场景不对、人物不对，还是镜别不对。
带着这个再去搜，比盲目换词快得多。

## 组方案：每一条都要能用

**同一条素材不能在一条方案里出现两次**——同一个画面在片子里出现两次，
一眼就能看出来。提交时会点名拒绝（如「素材 101 用了两次（U1 和 U2 的 S1）」）。
不同方案之间可以复用同一条素材。

**不做笛卡尔积。** 你提交的是一份完整方案列表，每条明确「U1 用什么、U2 用什么」。

为什么：笛卡尔积隐含「任意搭配都成立」，而上面第 ② 条说了那不成立。产品要求
是**产出的每一条都能用**，不是导 60 条挑 3 条。

```json
{
  "plans": [
    {
      "name": "A-厨房线",
      "units": [
        {"unit": 0, "mode": "whole", "material": 114799},
        {"unit": 1, "mode": "perShot", "shots": {"5": 116719}},
        {"unit": 2, "mode": "keepOriginal"}
      ]
    },
    {
      "name": "B-冰箱线",
      "units": [
        {"unit": 0, "mode": "whole", "material": 116833},
        {"unit": 1, "mode": "perShot", "shots": {"5": 116717}}
      ]
    }
  ]
}
```

规则：

- **没提到的单元自动保留原片**，不用显式写 `keepOriginal`
- **同一个单元在所有方案里要用同一种模式**——U1 在方案甲整体替换、在
  方案乙镜头替换，投影到审核页时摆不到一个位置上，提交会被拒
- `name` 必填且不能重名——**它就是导出的文件名**（`A-居家写实线.mp4`）。
  路径分隔符这类字符会被换成横杠，超过 60 字会截断；名字要能让人一眼
  认出这条片子是哪个路子。
  **撞名不会覆盖，会往后排**（`A-居家写实线(2).mp4`）：往同一个目录导第二批
  时上一批还在。所以导完要看 `results[].path`——那是**实际**落地的文件名，
  别照着方案名去猜
- **方案之间要有可见差异**。两条方案只差一个三秒镜头，等于导了两条一样的片子
- 每条方案内部要前后顺畅（第 ② 条）

校验不过会**一次列出所有问题**，改完整批重提。

## 交给人审核

**挑完候选不要直接导出。** 你挑的素材需要人过目——这是这条流水线里
人把关的一环，跳过它等于替用户拍板。两条路：

**① 快速把关（推荐）：`ishkafel review <task>`**

前提是你已经 `apply plans` 提交过方案——提交那一刻方案会**投影成任务的
替换现状**（`task` 输出里的 `replacements` 字段），审核页读的就是它。

弹出专门的审核界面：你挑的每条候选和原片对照摆开，人悬停播放、点击剔除、
一次确认。确认那一刻剔除落进 `replacements`——它是主流程的唯一真相。

**然后等用户发话。** 人审完会告诉你「审核完了，继续」。等不等、等多久、
超时怎么办，是你和用户之间约定的策略（比如用户说「一分钟没回你就直接导」），
软件不当流程裁判。

**剔了哪几条**：跑 `ishkafel task <task>` 看 `replacements`——你提交过的
素材 id 不在里面了，就是被人剔掉的。被剔除说明人不认可那一类选择——
**更新方案换掉它们再导**，不要把刚被剔掉的又换个 id 提上来。

**导出会替你把这道关**：方案里还引用着被剔除素材就跑 `export`，那条方案
会被点名拦下（退出码 2）——绝不会把人剔掉的素材静默导出去。

**人在审核台上指挥你剔除**：这是最常见的用法——人看着卡片墙说「第 3、
7、12 条删掉」，你去删。三条命令：

```bash
ishkafel review list <task>                      # 先看有哪些，带编号
ishkafel review drop <task> --items 0:-:100,1:2:202
ishkafel review keep <task> --items 0:-:100      # 剔错了恢复回来
```

编号是 `单元:镜头:素材`，整体替换的候选镜头位写 `-`；`list` 返回的 `ref`
可以原样喂回去，不用自己拼。**编号写错整批不落盘**并一次点名全部问题——
不会出现「以为删了三条实际删了一条」。

**人正开着审核页时，这两条命令走委派**：不是你写盘，是界面替你点。因为
审核页上剔掉的卡只是界面里的临时状态，**人按「确认」才落盘**——你绕过界面
写盘会让人还没确认盘上就变了。这时返回的 JSON 里 `delegated: true`，
**要如实转告人「已经标好了，按确认才生效」**，别报成「已删除」。

**互斥**：另一个 Agent 占着任务时你的写入会返回退出码 4——等它。
人开着界面**不算冲突**（上面那条委派路径），但人在工作台深度编辑时
`apply` / `export` 仍会返回 4。

**② 深度编辑：`ishkafel open <task>`**

把 app 弹出来落到完整工作台。人在那里能预览、能改切分、能换素材、能自己
导出。适合人要亲自动手调的场合；只是过目用 ①，别把人扔进编辑器。

**注意锁**：你在操作时任务是锁着的，人打开会看到只读横幅**并跟着你走**
（不是一张空白拦截页——人正是为了看你干活才打开的）；人可以强制接管，
之后你的写入会被拒绝。反过来，人正开着工作台时你的 `apply` / `export` 会返回
退出码 `4`——等它，或者让人先关掉。

锁会在持有者停止心跳 60 秒后自动失效，所以不会有永久卡死。

## 不要做的事

- **不要凭空造 id**。只能引用 `candidates` 返回过的素材 id、`task` 返回过的
  单元/镜头下标。校验会挡住，但那是在浪费一轮
- **不要替用户决定要不要导**。`export` 会先说「将导出 N 条到哪儿」，跑不跑
  是发起方的决定
- **不要在没有标签组的任务上硬挑**。先修标签组（切企业 → 重新 import）
- **不要绕过 CLI 直接改任务 JSON**。锁和校验都在 CLI 这一层，绕过去就没有保护了

## 时间：原片位置 vs 成片位置

任务 JSON 里每个单元、每一镜都给两套时间，**基准写在名字里**：

- `sourceStartMs` / `sourceEndMs`：**原片**位置。这是切分点，是存下来的数据。
- `composedStartMs` / `composedDurationMs`（镜头是 `composedEndMs`）：
  **成片**位置——这一段在最终片子里落到第几毫秒。界面上显示的就是这一套。

两者会差很多：手加的台词语义单元原片里没有它，整体替换那一段长度跟素材走，
调整顺序更是把后面全挪一遍。**判断「这一镜够不够铺满这句话」「前后连不连得上」
要用成片位置**——用原片位置会算错，而且不会有任何报错。

`startMs` / `endMs` 是老名字，等于 `sourceStartMs` / `sourceEndMs`，保留不动。

**成片位置可能整块没有**：整体替换的单元长度跟选中素材走，素材还没下到本地时
这个长度就是未知的，那时整条片子的成片位置都算不准。这种情况下所有
`composed*` 字段都不出现，顶层给一句 `composedUnavailable` 点名是哪几个单元
卡住了。**软件不会给你一个差不多的数**——你会拿它当真数用。
先 `candidates fetch` 把素材下下来，再来看。

整体替换的单元，它下面那些镜头**没有** `composedStartMs`：那一段整个换成了
另一条素材，原片的镜头切分在成片里已经不存在了。

界面上时间一律显示成 `分:秒.帧`（如 `01:36.07` = 1 分 36 秒第 7 帧），
不是百分之一秒。
